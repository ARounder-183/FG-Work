# 自习室 - 模块设计文档

> **项目**：在线自习室 + 发帖朋友圈 + 在线一起听歌
> **技术栈**：React + TypeScript + Next.js App Router + shadcn/ui + Prisma + SQLite
> **已完成**：用户模块（注册/登录/头像/个人信息）
> **文档覆盖**：发帖模块、打卡模块、一起听歌模块、排行榜模块

---

## 一、发帖模块

### 1.1 需求分析

用户需要一个类似"朋友圈"的内容分享功能，支持 Markdown 格式的发帖，附带图片，以及互动评论。这是站内用户交流的核心渠道。

**关键诉求：**
- 用 Markdown 写内容（技术感、排版能力强）
- 可以附带图片（支持拖拽或粘贴上传）
- 可以评论互动
- 帖子和评论都能看到作者信息（头像、用户名）

### 1.2 功能描述

| 功能 | 描述 |
|---|---|
| 发帖 | 标题 + Markdown 正文 + 可选图片。写作时实时预览 Markdown 效果。 |
| 图片上传 | 支持拖拽/粘贴/点击上传，本地存储到 `public/uploads/posts/`，自动生成时间戳文件名。单张不超过 5MB，每帖最多 9 张。 |
| 帖子列表 | 按时间倒序展示所有帖子，卡片式布局，显示标题、摘要（纯文本前 100 字）、首图、作者、时间、评论数 |
| 帖子详情 | 完整 Markdown 渲染内容 + 图片画廊 + 评论区 |
| 评论 | 文本评论（纯文本，不支持 Markdown，避免注入问题），可删除自己的评论 |
| Markdown 渲染 | 使用 `react-markdown` + `remark-gfm`，支持表格、代码高亮、任务列表 |

**API 路由：**
```
GET    /api/posts          → 帖子列表（分页，cursor-based）
POST   /api/posts          → 创建帖子（需登录）
GET    /api/posts/[id]     → 帖子详情
PUT    /api/posts/[id]     → 编辑帖子（仅作者）
DELETE /api/posts/[id]     → 删除帖子（仅作者）
GET    /api/posts/[id]/comments    → 评论列表
POST   /api/posts/[id]/comments    → 添加评论（需登录）
DELETE /api/posts/[id]/comments/[cid] → 删除评论（仅作者）
POST   /api/upload          → 上传图片，返回图片 URL
```

### 1.3 边界

**功能边界：**
- 仅支持单层评论（不嵌套回复，避免复杂度溢出）
- 不支持点赞/收藏/转发（MVP 不必要）
- 不支持话题/标签分类（可在后续版本加入）
- 图片不经过裁剪/压缩处理（保持原图，前端可限制尺寸展示）
- Markdown 中的图片仅支持已上传的 URL，不解析外部链接（安全考虑）

**数据边界：**
- 标题最长 100 字
- 正文最长 50000 字（Markdown 原始文本）
- 每帖最多 9 张图片
- 评论最长 500 字
- 分页：每页 20 条帖子

## 二、打卡与计时模块

### 2.1 需求分析

用户需要一个类似番茄钟的自习计时工具，可以选择学习主题，手动开始和结束计时，记录每天的学习时长。这是"自习室"的核心功能。

**关键诉求：**
- 手动开/关计时（不是倒计时番茄钟，而是累计计时）
- 可选择学习主题
- 记录每日学习时长，作为排行榜数据源
- 计时过程中可见，有仪式感

### 2.2 功能描述

| 功能 | 描述 |
|---|---|
| 主题管理 | 预设几个主题（编程、阅读、写作、语言学习、其他），用户可自定义新主题。每个主题可选一个 emoji 图标。 |
| 开始打卡 | 选择一个主题 → 点击"开始自习" → 计时器开始走动 |
| 计时中 | 显示当前已计时长（时:分:秒）、主题名称、开始时间。可切换主题（旧计时结束，新计时开始）。 |
| 结束打卡 | 点击"结束自习" → 显示本次时长统计 → 汇总到当日学习记录 |
| 今日统计 | 显示当日各主题学习时长分布（饼图或条形图） |
| 历史记录 | 日历视图 + 列表，可查看每一天的打卡详情 |

**计时逻辑：**
- 前端计时：`setInterval` 每秒更新，显示精确到时/分/秒
- 服务端记录：结束后上传 `startedAt` 和 `duration`（秒），单日同主题多次打卡自动累加
- 容错：如果页面关闭中断，开启时检查是否有未结束的打卡，提示是否继续或放弃

**API 路由：**
```
GET    /api/topics          → 主题列表
POST   /api/topics          → 创建新主题
GET    /api/checkin/active  → 获取当前进行中的打卡
POST   /api/checkin/start   → 开始打卡（需登录）
POST   /api/checkin/stop    → 结束打卡（需登录）
GET    /api/checkin/records → 打卡记录（支持日期筛选）
GET    /api/checkin/today   → 今日统计（各主题时长分布）
```

### 2.3 边界

**功能边界：**
- 不在服务端做"防作弊"（相信用户自律，后续可加）
- 不限制单次最长计时（但前端超 12 小时弹提示）
- 主题管理不设上限，不删除预置主题
- 计时不支持暂停（简化，要么继续要么结束）
- 今日统计数据每天午夜重置

**数据边界：**
- 时间精确到秒，前端显示精确到秒，排行榜精确到分钟
- 单次打卡记录时长不超过 86400 秒（24小时）

## 三、一起听歌模块

### 3.1 需求分析

用户希望和站内其他人一起听同一首歌，类似网易云音乐的"一起听"功能。一个人控制播放，其他人同步收听。

**关键诉求：**
- 搜索网易云歌曲
- 从歌单导入（网易云歌单 ID）
- 创建听歌房间，邀请他人加入
- 房主控制播放/暂停/切歌，其他人同步
- 同步精度：秒级即可，不需要毫秒级同步

### 3.2 功能描述

| 功能 | 描述 |
|---|---|
| 歌曲搜索 | 输入关键词，通过网易云 API 搜索单曲，列表展示（歌名、歌手、专辑封面） |
| 歌单导入 | 输入网易云歌单 ID，拉取歌单内所有歌曲 |
| 创建房间 | 用户创建听歌房间，成为房主。房间有名称 |
| 加入房间 | 查看在线房间列表，点击加入。一个房间理论上不限人数 |
| 播放控制 | 房主：播放/暂停/切歌/切换歌单中歌曲。通过 WebSocket 广播播放状态 |
| 同步播放 | 非房主：接收房主广播的状态更新，本地同步播放（使用网易云外链或 iframe 播放器） |
| 当前播放 | 显示当前歌曲信息（封面、歌名、歌手、进度条） |

**WebSocket 通信协议：**

| 事件 | 方向 | 数据 |
|---|---|---|
| `join-room` | 客户端 → 服务端 | `{ roomId, userId }` |
| `leave-room` | 客户端 → 服务端 | `{ roomId, userId }` |
| `play` | 房主 → 服务端 → 所有 | `{ songId, position }` |
| `pause` | 房主 → 服务端 → 所有 | `{ position }` |
| `seek` | 房主 → 服务端 → 所有 | `{ position }` |
| `next-song` | 房主 → 服务端 → 所有 | `{ songId, playlistIndex }` |
| `sync-state` | 服务端 → 客户端 | `{ songId, isPlaying, position, timestamp }` |
| `user-joined` | 服务端 → 所有 | `{ userId, username }` |
| `user-left` | 服务端 → 所有 | `{ userId, username }` |

**同步策略：**
- 房主动作立即广播，服务端记录当前状态
- 新加入者获取当前状态（`sync-state`），计算偏移后同步
- 每 30 秒服务端下发一次 `sync-state` 作为心跳和对齐
- 前端根据 `serverTimestamp` 和本地时间差计算实际播放位置

**音乐播放：**
- 使用网易云音乐官方 iframe 外链播放器（`//music.163.com/outchain/player`），受浏览器自动播放策略限制
- 备选方案：使用 HTML5 Audio API + 网易云歌曲直链（需要处理跨域和防盗链）

**API 路由：**
```
GET    /api/music/search?q=xxx       → 搜索歌曲
GET    /api/music/playlist?id=xxx    → 获取歌单详情
GET    /api/music/song?id=xxx        → 获取歌曲详情/播放链接
GET    /api/music/rooms              → 在线房间列表
POST   /api/music/rooms              → 创建房间（需登录）
GET    /api/music/rooms/[id]         → 房间详情
```

**WebSocket 端点：**
```
ws://localhost:3000/api/ws/music    → 听歌 WebSocket
```

### 3.3 边界

**功能边界：**
- 仅限房主控制播放，不支持多人协作控制
- 不使用 Spotify/Apple Music API（版权和复杂度问题）
- 网易云 API 使用第三方 `NeteaseCloudMusicApi` 包，受服务可用性限制
- 歌曲播放依赖网易云外链可用性，不可用时显示提示
- 不支持私人房间/密码房间（MVP 阶段）
- 歌曲不缓存到服务端，不保存播放历史

**技术边界：**
- WebSocket 基于 `next-ws` + `ws` 库实现
- 单房间理论上不限制人数，但实际受单线程 WebSocket 连接数限制（约 1000 连接）
- 网易云 API 请求需要代理（`NeteaseCloudMusicApi` 启动本地服务），考虑使用 Docker 或直接集成到 Next.js API 路由中
- 播放进度偏移容忍 ±3 秒

## 四、排行榜模块

### 4.1 需求分析

排行榜是激励用户自律学习的社交功能，通过可视化展示站内用户的学习时长排名和主题分布，促进良性竞争氛围。

**关键诉求：**
- 总学习时长排名（全站用户按总时长排序）
- 按主题查看时长分布和占比
- 数据来源：打卡模块的 `StudyRecord` 表

### 4.2 功能描述

| 功能 | 描述 |
|---|---|
| 总时长排行榜 | 全站用户按总自习时长降序排列。列表项：排名、头像、用户名、总时长（X小时Y分钟） |
| 主题时长排行 | 同一主题下各用户的时长排名。顶部可切换主题筛选。 |
| 主题占比图 | 饼图/环形图展示全站各主题的学时占比 |
| 个人排名 | 登录用户高亮显示自己在排行榜中的位置 |
| 时间周期 | 支持切换：本周 / 本月 / 全部时间 |

**API 路由：**
```
GET  /api/leaderboard?period=all&topic=all  → 排行榜数据
     period: "week" | "month" | "all"
     topic: "all" | topicId
```

**返回数据格式：**
```json
{
  "rankings": [
    { "rank": 1, "userId": "...", "username": "张三", "avatar": "...", "totalMinutes": 2340 },
    ...
  ],
  "myRank": { "rank": 5, "totalMinutes": 890 },
  "topicDistribution": [
    { "topicName": "编程", "totalMinutes": 4500, "percentage": 45 },
    { "topicName": "阅读", "totalMinutes": 2000, "percentage": 20 }
  ]
}
```

### 4.3 边界

**功能边界：**
- 排行榜每小时更新一次（不实时计算，避免性能开销；`StudyRecord` 按天汇总，天然支持离线计算）
- 仅显示前 100 名
- 不记录历史排名变化趋势（MVP 不必要）
- 数据仅来自打卡模块的已完成记录

**隐私边界：**
- 排行榜展示用户名和头像（已公开信息）
- 个人详细学习记录仅自己可见

### 4.4 界面设计

## 五、跨模块交互与全局约束

### 5.1 模块依赖关系

```
用户模块 ← 所有模块的基础（认证/个人信息）
    ├── 发帖模块（需要用户身份）
    ├── 打卡模块（需要用户身份）→ 排行榜数据源
    └── 听歌模块（需要用户身份）

打卡模块 → 排行榜模块（StudyRecord 表）
```

### 5.2 全局设计原则

- **认证**：所有需登录的 API 使用 `requireAuth()` 中间件统一处理
- **错误处理**：API 统一返回 `{ error: string }` 或 `{ data: T }` 格式
- **Toast 提示**：全局使用 sonner 的 `toast.success/error`
- **加载状态**：使用 shadcn Skeleton 组件作为加载占位
- **空状态**：每个列表页面有空状态设计（引导用户行动）

### 5.3 数据流

```
前端页面 → fetch API Route → requireAuth() → Prisma 查询 → 返回 JSON
                                                           ↓
音乐同步特殊流：                                       前端渲染
  房主操作 → WebSocket → 服务端广播 → 其他客户端同步更新
```

### 5.4 尚未明确的设计决策（需要后续讨论）

| 决策项 | 当前状态 | 选项 |
|---|---|---|
| 音乐播放器实现 | 待定 | A) 网易云 iframe 外链（简单，受浏览器限制） B) HTML5 Audio + 歌曲直链（灵活，需处理防盗链） |
| 排行榜实时性 | 建议离线计算 | 每小时更新 vs 实时查询 |
| 发帖是否支持草稿 | MVP 不做 | 本地 localStorage 草稿 vs 服务端草稿 |
| PWA 支持 | MVP 暂不考虑 | 后续可加离线能力和桌面安装 |
